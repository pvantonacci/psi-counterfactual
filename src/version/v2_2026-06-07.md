### Modified scripts

#### `src/02_counterfactual_pipeline.py`

- **Added `_CHARLSON_PREFIXES` module-level constant** — 17-category Charlson ICD-10-CM mapping (Quan et al. 2005) with standard weights. Defined outside `_run_pipeline()` so it's constructed once per process.
- **Added `_charlson_from_codes()` helper** — vectorised prefix matching; applies standard Charlson hierarchy (complicated DM suppresses uncomplicated DM; moderate/severe liver suppresses mild liver; metastatic cancer suppresses non-metastatic malignancy).
- **Stage 2a feature matrix** — extended `build_features_at_tstar()` with a pre-existing comorbidity block:
  - Classifies diagnoses as pre-existing (DX_CHRONIC='YES' or DX_DATE < t0 or DX_STATUS POA).
  - Adds `charlson_score` (integer, Quan weights), `n_preexisting_dx` (count), and 17 binary `cs_<category>` flags to every feature vector.
  - **No post-event leakage** — only diagnoses satisfying pre-admission criteria are used; the 4h cutoff window still applies for all other features.

**Stage 1 CEM note:** CEM strata are unchanged. The `n_chronic_bin` from problem lists serves as the comorbidity proxy for stratum matching (already present in v1). Adding a Charlson-based stratum would require loading donor diagnoses before Stage 2a (circular dependency in Snowflake mode) and would fragment strata, reducing matchable donor pool. The Charlson score enters the pipeline via the propensity-score feature matrix (Stage 2b) instead, where it improves distance estimation without reducing eligible matches.

#### `src/07_timestamp_distribution_analysis.py`

- **Added `classify_preexisting_dx()` helper** — same 4-rule classification as 08_; vectorised with pandas merge for Rule 4 (problem list cross-reference).
- **Added OMNY_ID to encounters read** — needed for problem-list cross-reference (Rule 4); falls back gracefully if column absent.
- **Added `problem_lists.csv` load** — loaded early, passed to `classify_preexisting_dx()` for Rule 4; skipped if file not found.
- **Extended diagnoses.csv read** — added `DX_CHRONIC` and `DX_STATUS` columns (graceful fallback if absent).
- **Added section [1b] Diagnosis Classification** — classifies every diagnosis row; splits into `dx_preexisting` / `dx_encounter` subframes; collects separate summary stats; generates `ts_dx_classification.png` (2-panel: pre-existing left, encounter-driven right).
- **Auto-included in report** — `save_fig()` adds the new figure to `saved_figures`; report writer iterates over this list, so the new section appears automatically after `ts_diagnoses.png`.

**Why more cases in v2?** The Snowflake re-pull (2026-06-07) fetched all 255 PSI case encounters into `encounters.csv`, not just the 145 that were present in v1. After governance filtering and t0/E_TIME validation, 168 cases now enter the matching pipeline (vs 110 in v1). 7 of those 168 found no matching donors after Stage 2c (161 rank-1 pairs).

**Why more pairs per case?** The Charlson/comorbidity features added to Stage 2a produce a better-calibrated propensity score. Cases that previously fell outside the caliper now find donors within it, and each matched case tends to retain more of its top-k donors.
