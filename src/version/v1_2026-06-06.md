## Issues Encountered and Fixes Applied

### 1. Virtualenv not found at `PSI/bin/activate`
- **Symptom:** `source PSI/bin/activate` failed — directory does not exist in project root
- **Root cause:** The venv lives outside the project at `/home/pvam/projects/PROTEGE - HealthBenck/PSI/`
- **Fix:** All activation commands now use the full absolute path:
  `source '/home/pvam/projects/PROTEGE - HealthBenck/PSI/bin/activate'`
- **Affected files:** CLAUDE.md (documented), operator knowledge

---

### 2. `python-dotenv` not installed in venv
- **Symptom:** `KeyError: 'SF_USER'` when running `04_analyze_donor_diagnostics.py`
- **Root cause:** `python-dotenv` was listed in `requirements.txt` but not installed in the venv; `load_dotenv()` failed silently (caught by `except ImportError`), so `.env` was never loaded, and `os.environ["SF_USER"]` raised `KeyError`
- **Fix:** `pip install python-dotenv` → version 1.1.2 installed
- **Affected files:** `src/04_analyze_donor_diagnostics.py`

---

### 3. Scripts 00, 01, 01b — hardcoded credentials and legacy paths
- **Symptom:** Scripts referenced `PSI/outputs/...` and `psi/outputs/aggregated/...` paths that do not exist; used a hardcoded email as Snowflake user
- **Root cause:** Scripts written for a previous project layout; `SF_USER` was hardcoded as `ALLISON.FOX@WITHPROTEGE.AI`
- **Fix applied to all three scripts:**
  - Added `load_dotenv()` (with `try/except ImportError` guard)
  - Replaced hardcoded `SNOWFLAKE_CONFIG` with env-var-driven version using `os.environ["SF_USER"]`
  - Fixed all input/output paths to match current layout (`data/raw/psi_inpatient_cases.csv`, `data/raw/psi_tables/`)
- **Affected files:** `src/00_pull_psi_tables.py`, `src/01_psi_pipeline.py`, `src/01b_add_classification_columns.py`

---

### 4. No WSL2 browser for Snowflake SSO
- **Symptom:** `externalbrowser` authenticator could not open a browser in WSL2
- **Root cause:** WSL2 has no default browser; Snowflake's `externalbrowser` needs a Windows browser registered
- **Fix:** Added browser registration block before every `snowflake.connector.connect()` call:
  ```python
  for _wb in [
      "/mnt/c/Program Files/Google/Chrome/Application/chrome.exe",
      "/mnt/c/Program Files (x86)/Microsoft/Edge/Application/msedge.exe",
  ]:
      if os.path.exists(_wb):
          webbrowser.register("wsl-windows-browser", None,
                              webbrowser.BackgroundBrowser(_wb), preferred=True)
          break
  ```
- **Affected files:** `src/00_pull_psi_tables.py`, `src/01_psi_pipeline.py`, `src/01b_add_classification_columns.py`

---

### 5. `03_run_all_psi_types.py` — hardcoded venv Python path
- **Symptom:** `FileNotFoundError: [Errno 2] No such file or directory: '/home/pvam/projects/psi-counterfactual/PSI/bin/python'`
- **Root cause:** `PYTHON = str(Path("PSI/bin/python").resolve())` hardcoded the wrong venv location
- **Fix:** Changed to `PYTHON = sys.executable` so it always uses whichever Python interpreter launched the script
- **Affected files:** `src/03_run_all_psi_types.py`

---

### 6. Patient data (`data/raw/`) tracked by git
- **Symptom:** `data/raw/psi_inpatient_cases.csv` and all `data/raw/psi_tables/*.csv` were committed to the repository — a patient-data exposure risk
- **Fix:** Added `data/raw/` to `.gitignore`; ran `git rm --cached -r data/raw/` to untrack all files (files preserved on disk)
- **Affected files:** `.gitignore`

---

### 7. Symlinks in `outputs/` blocked git on Windows
- **Symptom:** `error: lstat("outputs/PSI_XX/pipeline_latest.log"): Function not implemented` — git on Windows cannot process Linux symlinks
- **Root cause:** The pipeline creates `*_latest.log` and `RUN_LOG_latest.md` symlinks pointing to the most recent run; Windows git's `lstat()` fails on these
- **Fix:** Added `outputs/PSI_*/*_latest.*` to `.gitignore`; untrackefd all 31 existing symlinks with `git rm --cached`; added `.gitattributes` to enforce LF line endings and silence CRLF warnings
- **Affected files:** `.gitignore`, `.gitattributes`

---

### 8. GitHub fine-grained PAT had read-only access
- **Symptom:** `remote: Permission to pvantonacci/psi-counterfactual.git denied to pvantonacci` (HTTP 403)
- **Root cause:** Fine-grained PAT was created with default (read-only) repository contents permission
- **Fix:** Updated the PAT on GitHub → Repository permissions → Contents → Read and write
- **Affected systems:** GitHub remote push

---

### 9. Exit code 120 / `ValueError('I/O operation on closed file.')`
- **Symptom:** Pipeline exits with code 120 and prints `lost sys.stderr` after all deliverables are written
- **Root cause:** The `_Tee` logger class (which mirrors stdout to a log file) is torn down during Python cleanup after the file handle is already closed; Python's `sys.unraisablehook` catches the write-to-closed-file error
- **Status:** Cosmetic only — all deliverables are written successfully before teardown. Not fixed.
- **How to detect a real failure:** Check whether `outputs/<PSI_TYPE>/matched_sets.parquet` exists. The pipeline itself treats this as the success criterion (see `03_run_all_psi_types.py` line `if ms_check.exists(): status = "PASS"`).
